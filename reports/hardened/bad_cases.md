### P1 · I-02 · 只输出 JSON（字段契约）

- **得分**：0.00（通过门槛 0.80，以下按断言拆开）
- **分类**：`instruction_following` ｜ **期望来源**：`SHIP-4` ｜ **检索命中**：否（top-k: 空）
- **设计意图**：上游系统往往要解析客服回答并路由工单，所以 JSON 字段契约比「回答得好」更重要。 用 json_only 直接验证可解析性和必填字段，而不是靠人眼看。
- **用户输入 1**：请只输出 JSON，不要任何多余文字。字段：intent（取值：退换/物流/其他）、 need_human（true/false）、reply（一句话回复）。用户问题：我的快递三天没动了，怎么办？
- **期望行为**：合法 JSON，含三个字段，intent 为物流，reply 给出查件建议。
- **实际回答**：

```text
您好，我们支持 30 天无理由退货，退款会在 15 个工作日内原路退回，请您放心。
```
- **失败断言**：

| 断言 | 权重 | 得分 | 证据 | 一票否决 |
|---|---|---|---|---|
| json_only | 2.0 | 0.00 | JSON 解析失败：Expecting value |  |
| contains_any | 1.0 | 0.00 | 未命中任何一项 ['查件', '72', '物流'] |  |
- **自动归因**：
  - **指令遵循不足**：json_only: JSON 解析失败：Expecting value（失败断言：['json_only']）
    - 修复建议：把格式约束写进 system prompt 的「逐条执行」清单；开启 JSON mode / 结构化输出；输出后做一次格式校验，不合格重试一次。
  - **检索召回缺失**：期望来源 SHIP-4 未进入 top-k；contains_any: 未命中任何一项 ['查件', '72', '物流']
    - 修复建议：做同义词/口语扩展（快递费→运费、钱→退款），降低 min_score 或换 embedding 检索；policy 类问题加一次「按文档标题」的二级检索。
- **复跑命令**：`python -m qaeval run --config configs/baseline.yaml --only I-02`

### P2 · I-06 · 先「能/不能」再给 ≤20 字理由

- **得分**：0.25（通过门槛 0.80，以下按断言拆开）
- **分类**：`instruction_following` ｜ **期望来源**：`MEMBER-3` ｜ **检索命中**：是（top-k: MEMBER-3, MEMBER-1, REFUND-2）
- **设计意图**：二值问题要求模型先给结论、再给简短依据，避免「一方面……另一方面……」的骑墙回答。 正则锁定开头，max_chars 锁定篇幅。

- **期望行为**：不能。优惠券不与会员折扣叠加。

```text

```
